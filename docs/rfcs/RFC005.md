# RFC005 — 按 Sheet 纠错表头行（RFC003-C）

> **状态**：`[已实施]`  
> **提出日期**：2026-09-14  
> **锁定日期**：2026-09-14  
> **关联**：[`RFC003`](file:///e:/AIProject/File%20Desensitization/docs/rfcs/RFC003.md) 阶段 C；[`RFC004`](file:///e:/AIProject/File%20Desensitization/docs/rfcs/RFC004.md) 效果对比 Tab

---

## 1. 问题

自动识别已按 Sheet 独立判断，多数文件无需用户干预。

少数情况下：某个 Sheet 识别错了，但其它 Sheet 是对的。  
现有「手动指定第 N 行」会套用到**整本文件**，会连累本来识别正确的 Sheet。

---

## 2. 已锁定方案

**默认继续智能识别；只在个别 Sheet 识别错时再改。**

不是上传前让用户给每个 Sheet 填行号。

### 2.1 产品流程

1. 上传 → 默认 `auto`，每 Sheet 自动识别  
2. 处理完成 → 效果对比 Tab 展示各 Sheet 表头行（RFC003-B / RFC004）  
3. 若某 Sheet 不对 → 在该 Tab 内改成第 N 行 → **仅用原文件重跑该任务**  
4. 未改过的 Sheet 仍走自动识别（或保留全局 manual，若用户当初选了全书统一行号）

### 2.2 解析优先级

对每个 Sheet：

1. **`header_row_overrides[sheet]`**（用户纠错）  
2. 否则若 `header_row_mode=manual` 且有全局 `header_row` → 用全局行号  
3. 否则 → `detect_header_row()`

### 2.3 API

- 任务模型增加 `header_row_overrides: Dict[str, int]`
- `POST /api/tasks/{task_id}/reprocess`：合并某 Sheet 覆盖行号（或清除覆盖），重置任务并重新入队  
- Diff / 任务列表返回 `header_row_overrides`，便于 UI 标注「已手动纠错」

### 2.4 前端

- 效果对比当前 Tab：展示识别结果 + 行号输入 +「按此行重跑」  
- 若该 Sheet 已有覆盖：显示「恢复自动识别」

---

## 3. 明确不做

- 不做上传前「每个 Sheet 预先配置行号」的复杂表单  
- 不做所见即所得表格预览编辑器  
- 不按 Sheet 单独排队（重跑仍是整文件一次处理，仅解析时按 Sheet 用不同行号）

---

## 4. 验收标准

1. 默认行为不变：不传 overrides 时与 RFC003 自动识别一致。  
2. 只覆盖 SheetA 时，SheetB 仍自动识别。  
3. 效果对比可发起纠错重跑，完成后 Diff 刷新。  
4. 「恢复自动」清除该 Sheet 的 override 后重跑，回到自动结果。  
5. 自动化测试覆盖 overrides 优先级与引擎行为。
