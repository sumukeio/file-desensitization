# RFC003 — 智能识别表头所在行（阶段 A）

> **状态**：`[已实施]`  
> **提出日期**：2026-09-14  
> **锁定日期**：2026-09-14  
> **关联背景**：部分 Excel 报表并非“第 1 行就是表头”，常见结构为“标题行 + 空行 + 真正表头 + 数据行”。

---

## 1. 问题是什么

当前引擎默认把 **第 1 行** 当作表头。

但实际业务里，经常出现：

1. 第 1 行是报表标题；
2. 第 2 行是空行；
3. 第 3 行才是真正的列名；
4. 第 4 行开始才是数据。

这会带来 3 个直接问题：

- 真实表头可能被当成普通数据去脱敏；
- `ASIN`、`店铺`、`团队` 之类的列名匹配会失效；
- 若用户勾选“列名脱敏”，系统会改错行。

---

## 2. 目标

让系统在大多数常见 Excel 报表中，能更稳地识别“哪一行才是真正的表头”，同时保留人工兜底能力。

---

## 3. 已锁定方案：阶段 A

采用 **“自动识别 + 用户可手动指定”** 的半自动方案。

### 3.1 默认行为

- 默认开启：**自动识别表头所在行**
- 若用户不满意，可手动指定：`表头在第 N 行`

### 3.2 自动识别范围

- 默认只扫描每个 Sheet 的前 **15 行**
- 在这 15 行里，为每一行计算“像不像表头”的分数
- 取得分最高的一行，作为该 Sheet 的表头行

### 3.3 打分信号（启发式）

对每一候选行，综合以下信号加权打分：

1. **非空单元格数量多**  
   真表头通常不是只写 1 个标题，而是多列都有内容。

2. **文本比例高、数字比例低**  
   表头更像“店铺、团队、销售额、毛利率”；数据行更像数字。

3. **命中已知表头关键词**  
   如 `ASIN`、`店铺`、`团队`、`销售额`、`毛利率`、`负责人` 等。  
   本项目现有 `KNOWN_HEADERS_KEYWORDS`、`PSEUDO_COLUMN_MAPPING` 可直接复用为加分项。

4. **下一行更像数据**  
   若候选行下面一行开始出现较多数字、编号、金额、百分比，则候选行更可能是表头。

5. **标题行降权**  
   若一行只有 1 个非空单元格，且像“店铺汇总（1-8月）按累计销售额降序”这种长说明，则更像标题而非表头。

6. **空行跳过**  
   全空行不参与竞争。

### 3.4 表头上方区域如何处理

一旦识别出表头在第 `N` 行：

- 第 `1 ~ N-1` 行视为**标题区 / 说明区**
- 默认**不参与列语义匹配**
- 也不应被误当成普通数据批量脱敏

### 3.5 用户手动兜底

上传区增加一个可选项：

- `表头位置：自动识别 / 手动指定`
- 若选手动指定，再输入 `第几行`

这样即使碰到极少数复杂报表，用户也能一键纠正。

---

## 4. 为什么选这个方案

这是业界里比较稳妥、也最好解释的做法。

常见成熟产品并不会只靠“纯自动猜”，而是：

- 先自动判断；
- 再允许用户改掉；
- 避免把复杂 Excel 全押在黑盒算法上。

对本项目来说，这种方案有 4 个优点：

1. **准确率更高**：比“永远第 1 行”稳很多；
2. **用户能理解**：规则清晰，不神秘；
3. **容易测试**：可以为“标题 + 空行 + 表头 + 数据”写稳定回归用例；
4. **兼容现有架构**：只需扩展 `ExcelProcessor` 的表头识别逻辑与前端参数。

---

## 5. 本次明确不做

- 不处理真正的**多级表头**（如第 3 行大类、第 4 行子类）
- 不做 LLM / 机器学习表头识别
- 不做所见即所得表格预览编辑器
- 不承诺 100% 零误判，必须保留手动指定兜底

---

## 6. 实施建议

### 6.1 后端

- 在 `ExcelProcessor` 中新增 `detect_header_row()` 之类的方法
- 返回每个 Sheet 的：
  - `header_row_index`
  - `header_values`
  - `reason / score`（可选，仅调试或日志用）

### 6.2 前端

- 上传区新增：
  - `表头位置：自动识别 / 手动指定`
  - 若手动指定，则输入行号

### 6.3 与 RFC001 的关系

RFC001 解决的是：**要不要脱敏列名**

RFC003 解决的是：**列名到底在哪一行**

二者是上下游关系，但不是同一件事。

正确顺序应是：

1. 先识别出真正的表头行；
2. 再决定是否对该行做“列名脱敏”。

---

## 7. 验收标准（摘要）

1. 对“标题行 + 空行 + 表头 + 数据”的常见结构，能自动识别出真实表头行。
2. 自动识别后，数据行实体匹配恢复正常（如 `ASIN` / `店铺` 列仍能正确假名化）。
3. 勾选“列名脱敏”时，应处理识别出的真实表头行，而不是固定第 1 行。
4. 用户可切换为手动指定表头行，且指定后优先级高于自动识别。
5. 新增自动化测试覆盖标题行、空行、手动指定、识别失败兜底等场景。

---

## 8. 多 Sheet 场景与产品路线（已锁定）

同一本 Excel 里，不同 Sheet 的表头行可能不同（例如 Sheet1 在第 1 行，Sheet2 在第 3 行）。

### 8.1 当前引擎能力

**默认「自动识别」已按 Sheet 分别判断**，可以应付混合结构。

「手动指定第 N 行」是整本文件共用一个行号，**不适合**混合 Sheet；此时应保持自动识别。

### 8.2 产品路线（A → B → C）

| 阶段 | 内容 | 状态 |
| :--- | :--- | :--- |
| **A** | 上传区说清楚：默认自动、按 Sheet 单独判断；混合结构请用自动 | 本期落地 |
| **B** | 处理完成后展示各 Sheet 识别到的表头行（建立信任） | 本期落地 |
| **C** | 按 Sheet 单独纠错行号（默认自动，仅改错的） | 已由 [`RFC005`](file:///e:/AIProject/File%20Desensitization/docs/rfcs/RFC005.md) 落地 |

**判断（已落实）**：C ≠ 每个 Sheet 都要用户选；C = 默认智能识别 + 仅对识别错的 Sheet 在效果对比里纠错重跑。
